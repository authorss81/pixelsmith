# core/contract/json-fields.txt — the engine's JSON contract, and the Dart member
# that carries each of its fields.
#
# THE COMMITTED SIDE OF THE JSON DRIFT CHECK. Read this before editing it.
#
# Every row is one field or enum variant the engine emits across the FFI, and the
# Dart symbol in the second column that models it. `scripts/check-json-contract.sh`
# runs `cargo run --bin px-json-dump -- --check` against this file, and that is
# wired into `scripts/verify.sh` as a FAILURE — not a note, which is what
# `check-dart-bindings.sh` gets in section 3b.
#
# WHY THE COMMITTED SIDE LIVES HERE AND NOT IN app/.
#
# `app/` is the `authorss81/shrinkray` submodule: a separate repository this
# pipeline can read and cannot push to. A check whose answer depends on what that
# repository contains is a check that cannot fail, because the only available
# response to a red result is a commit nobody can make. Five phases of drift
# (06, 07, 12, 13, 14) accumulated behind exactly that, while the C ABI check
# reported "15 entry points match". This file is landable, so the check is a hard
# gate; the Dart half it describes is delivered as a patch under
# `workspace/phase-20/`.
#
# FORMAT
#
#   <engine path> TAB <Dart symbol>
#
# The engine path is what `px-json-dump` prints: `Owner.field` for a struct field,
# `Owner.outer.inner` for a nested one, `Owner::variant` for an enum variant. A
# second tab and free text are allowed and ignored; use them to say why a
# surprising row is what it is.
#
# A row with nothing after the tab is a FAILURE. A row naming a path the engine
# no longer emits is a FAILURE. Both directions are checked, so this file cannot
# rot into a claim nobody maintains.
#
# WHY THE NAMES COME FROM SERDE, NOT FROM PARSING THE SOURCE
#
# `core/src/ffi_json.rs` asks serde by serialising a representative instance of
# each type and reading the keys back, so `rename_all`, `tag`, `flatten` and
# `Option` are applied by the same code that applies them on the wire. A source
# parser would have to re-implement all four and would eventually disagree with
# serde — reporting drift that is not there, which is the failure mode a drift
# check must not have. Note `ColourSpace::display_p3` and not `DisplayP3`: that
# spelling is the engine's, and a Dart side that guessed `displayP3` would get a
# refusal naming a space that does not exist.
#
# TO ADD A ROW
#
# 1. Add the field to the engine struct. `ffi_json` picks it up on the next run.
# 2. Run `bash scripts/check-json-contract.sh --write` to append the new row.
# 3. Add the Dart member, in `app/lib/rust/models.dart`, and land the patch in
#    the app repository.
# 4. Run `bash scripts/check-json-contract.sh` again. It passes when every engine
#    field has a Dart member named here.
#
# The 278 rows below are the whole of the JSON that crosses the boundary. A new
# one appearing in column one with nothing in column two is the phase-21
# equivalent of the defect this file exists to catch.
